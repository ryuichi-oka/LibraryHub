# LibraryHub 要件定義（初版）

## 1. 目的・スコープ
- LibraryHub は、蔵書の管理、検索、貸出/返却の運用を一元化する図書アプリである
- 最終目的は、社内での読書習慣を活性化することである
- 本要件は MVP（最小実用プロダクト）を対象とし、まずは日常運用に必要な基本業務をカバーする
- 本システムの利用スコープは社内利用に限定する
- 対象外（初期段階）:
  - 外部図書館システムとの連携
  - 有料決済
  - 社外公開を前提とした機能
  - 高度なAIレコメンド機能

## 2. 想定ユーザー
- 管理者:
  - 蔵書データ管理、利用者管理、運用設定を行う
- 一般利用者:
  - 蔵書検索、貸出状況の確認、予約や返却期限の確認を行う

## 3. 機能要件

### 3.1 認証・権限
- FR-001: ユーザーはログインして利用する
- FR-002: ロール（管理者/一般利用者）ごとに利用可能機能を制御する
- FR-003: 管理者はユーザーの有効/無効を切り替えできる
- FR-004: MVP の認証方式はアプリ独自ログイン（メールアドレスまたは社員ID + パスワード）とする
- FR-005: 将来拡張として社内 SSO 連携を検討対象に含める

### 3.2 蔵書管理
- FR-010: 管理者は蔵書を登録/編集/削除できる
- FR-011: 蔵書は少なくとも以下の項目を保持する
  - 書籍ID
  - 書名
  - 著者
  - ISBN（任意）
  - 出版社（任意）
  - 出版年（任意）
  - カテゴリ
  - 保管場所（任意）
  - 利用状態（貸出可能/貸出中/予約あり/無効）
- FR-012: 同一タイトルの複本（複数冊）を管理できる

### 3.3 検索・一覧
- FR-020: 利用者は書名、著者、ISBN、カテゴリで蔵書検索できる
- FR-021: 検索結果には貸出可否と基本情報を表示する
- FR-022: 条件（カテゴリ、貸出状態）で絞り込みができる

### 3.4 貸出・返却・予約
- FR-030: 利用者は貸出可能な蔵書を貸出申請できる
- FR-031: 管理者は貸出処理と返却処理を実行できる
- FR-032: 返却期限を設定し、期限超過を判定できる
- FR-033: 貸出中の蔵書に対して予約を受け付けできる
- FR-034: 返却完了時に次予約者へ通知対象として記録し、MVP ではアプリ内通知を行う
- FR-035: 貸出上限は 1 利用者あたり 3 冊とする
- FR-036: 貸出期間は 14 日とする
- FR-037: 延長は 1 回まで可能とし、延長期間は 7 日とする
- FR-038: 次予約がある蔵書は延長不可とする

### 3.5 通知・リマインド
- FR-040: 返却期限が近い利用者を抽出できる
- FR-041: 期限超過の利用者を抽出できる
- FR-042: 通知履歴（対象、日時、種別）を保持する
- FR-043: MVP の通知方式はアプリ内通知のみとする
- FR-044: 次期改修要件としてメール通知を検討対象に含める
- FR-045: 延滞判定は返却期限の翌日から開始する
- FR-046: 延滞中の利用者には 3 日ごとにアプリ内督促通知を送る
- FR-047: 延滞中の利用者は新規貸出不可とし、返却完了時に貸出制限を解除する
- FR-048: 延滞に対する金銭ペナルティは設けない

### 3.6 履歴・監査
- FR-050: 貸出/返却/予約の履歴を参照できる
- FR-051: 管理操作（蔵書更新、ユーザー状態変更）の操作履歴を記録する

### 3.7 新着・おすすめ表示
- FR-060: 利用者向けに新着書籍一覧を表示できる
- FR-061: おすすめ書籍を表示できる
- FR-062: おすすめは「社内人気（貸出数が多い順）」と「管理者ピックアップ」を組み合わせたハイブリッド方式で表示する
- FR-063: おすすめ表示の内訳（人気枠/ピックアップ枠の件数）は設定で変更できる
- FR-064: おすすめ表示の初期比率は「人気枠 70% : ピックアップ枠 30%（7:3）」とする

## 4. 非機能要件
- NFR-001: 主要画面（一覧/検索）の通常操作は 3 秒以内で応答する
- NFR-002: 認証情報は平文保存しない（適切なハッシュ化）
- NFR-003: 権限外操作は拒否し、監査可能なログを残す
- NFR-004: 日次バックアップを取得し、復旧手順を定義する
- NFR-005: 日付・時刻は `Asia/Tokyo` を基準タイムゾーンとして扱う

## 5. 運用要件
- OPS-001: 管理者は運用上必要なマスタ（カテゴリ等）を更新できる
- OPS-002: 障害時に最小限の業務継続ができるよう、手動運用手順を整備する
- OPS-003: リリースごとに変更点と影響範囲を記録する

## 6. 前提・制約・未確定事項
- AC-001: 初期リリースは単一組織内利用を想定する（確定）
- AC-002: 通知方式は「MVP: アプリ内通知のみ」で確定し、次期改修でメール通知を検討する
- AC-003: 貸出ルールは「上限 3 冊 / 期間 14 日 / 延長 1 回まで（7 日） / 次予約ありは延長不可」で確定
- AC-004: 延滞運用は「期限翌日から延滞 / 3 日ごと督促 / 延滞中は新規貸出不可 / 金銭ペナルティなし」で確定
- AC-005: おすすめアルゴリズムは「人気 + 管理者ピックアップ」のハイブリッドで確定
- AC-006: おすすめ初期比率は「人気 70% : ピックアップ 30%（7:3）」で確定
- AC-007: 認証は「MVP: アプリ独自ログイン」で確定し、将来拡張で社内 SSO 連携を検討する
- AC-008: 技術スタックは `Next.js + Go + Nginx + PostgreSQL` で確定
- AC-009: 開発環境は `WSL2 + Dockerコンテナ` を前提とする

## 7. 受け入れ基準（MVP）
- CA-001: 管理者が蔵書を登録し、利用者が検索して貸出/返却できる
- CA-002: 貸出中・期限超過・予約状態が一覧で判別できる
- CA-003: 管理操作と貸出関連の履歴を参照できる
- CA-004: ロールごとの権限制御が有効である
- CA-005: 利用者が新着書籍とおすすめ書籍を確認できる
- CA-006: 延滞判定、督促通知、貸出制限/解除が要件どおりに動作する
- CA-007: 独自ログインで認証でき、ロールに応じた機能制御が行われる
