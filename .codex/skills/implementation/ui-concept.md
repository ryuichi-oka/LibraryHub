# UI Concept（LibraryHub）

この文書は、LibraryHub の画面実装でデザインの一貫性を維持するための基準である。
画面実装時は本ファイルを必ず読み、既存のトーンから逸脱しないこと。

## 1. 目指す印象
- 親しみやすい
- 清潔感がある
- 業務利用として信頼できる
- 派手すぎず、安っぽくない

## 2. 基本トーン
- 全体は白基調（`bg-slate-50` 〜 `bg-white`）
- 文字は真っ黒を避け、`slate` 系（例: `#334155`, `#475569`）を基本にする
- 主操作（Primary CTA）は明るめのブルー系
- 彩度の高い面積色は最小限にする

## 3. タイポグラフィ
- ベースフォントは丸みのある日本語対応フォントを優先
  - 例: `M PLUS Rounded 1c`, `Hiragino Maru Gothic ProN`
- 見出しは太めだが詰まりすぎない字間にする
- ラベル・本文・補助文で明確に階層を分ける
- ログイン見出しのような節タイトルには、必要に応じて薄いアクセント線を使う

## 4. レイアウト・余白
- レイアウトはシンプルな中央寄せを基本にする
- カードUIは角丸と控えめな影で整理する
- 余白は Tailwind で統一し、詰めすぎない
- 情報は縦方向に自然なリズムで配置する

## 5. コンポーネント設計方針
- 構成は `Tailwind CSS + CSS Module`
- 共通的な余白/配置/色は Tailwind 優先
- Tailwind で表現しづらい装飾（グラデーション、微細なタイポ調整、背景演出）は CSS Module へ分離
- `global.css` は最小限（ベースフォント・最低限の全体設定）にとどめる

## 6. フォームUI方針
- 入力欄は可読性最優先（十分な高さ、余白、プレースホルダのコントラスト）
- フォーカスリングは控えめかつ認識しやすくする
- エラー/成功表示は背景色 + 境界線 + 文字色で状態を明確に区別する
- ボタン文言は読みやすさ優先（太さ・字間を適正化）

## 7. 禁止・非推奨
- 真っ黒文字（`#000` 相当）の多用
- 極端に強い彩度・コントラストの多用
- 装飾を増やしすぎて情報優先度が崩れるデザイン
- 画面ごとにフォント・色・余白ルールが大きく変わる実装

## 8. 運用ルール
- 新規画面実装時は、この文書を先に読み、適用方針を決める
- 既存画面の改修でも、トーンの不一致が出る場合は本方針へ寄せる
- コンセプト更新が必要なときは、変更理由を短く記録してこの文書を更新する
