# UI Style Guide（実装ルール）

この文書は、画面実装時に「余白」「タイポグラフィ」「サイズ感」を揃えるための実装ガイドである。  
対象は `WEB` レイヤーのみ。`API / BATCH / DOCS` タスクでは参照しない。

## 1. 適用範囲
- 対象: 画面実装（新規画面、既存画面改修、UI調整）
- 非対象: API実装、バッチ実装、ドキュメント整備のみの作業

## 2. 基本原則
- まず既存画面（特にログイン画面）の余白・文字階層を優先して合わせる
- 新しい値を増やす前に、既存で使っている値を再利用する
- 余白は Tailwind 優先、再利用したい微調整のみ CSS Module へ切り出す

## 3. 余白ルール（フォームカード）
- カード外側:
  - 既定値は `px-5 py-8 sm:px-8`
- カード内側:
  - 既定値は `px-6 pt-4 pb-6 sm:px-7 sm:pt-5 sm:pb-7`
- フォーム内の縦間隔:
  - 「入力ブロック単位（label + input）」で揃える
  - 既定値は `gap: 1.25rem`（または Tailwind の `gap-5` 相当）
- 注意文・エラー文・成功文:
  - 個別 `margin-top` を乱立させず、親コンテナの `gap` で管理する

## 4. タイポグラフィルール
- 見出し:
  - 太めのウェイトを使い、`slate`/`blue` 系で階層を表現する
- ラベル:
  - `0.9rem` 前後、`font-weight: 700` を基本
- 補助文:
  - `0.88rem`〜`1rem` を基本にし、主情報より強くしない
- フォント:
  - `M PLUS Rounded 1c` と既存フォールバックを維持する

## 5. サイズルール（入力・ボタン）
- 入力欄:
  - 十分なタップ領域を確保（縦 `0.72rem` 前後の padding）
  - 角丸は既存画面に合わせて `0.75rem` 前後
- 主要ボタン:
  - 角丸・フォントウェイト・グラデーションは既存画面と同系統に揃える

## 6. 実装時チェックリスト
- 画面の外側余白は既定値に揃っているか
- カード内余白は既定値に揃っているか
- 入力ブロック間の余白は統一されているか
- ラベル/本文/補助文の文字サイズがバラついていないか
- 注意文/エラー/成功表示の余白管理が一貫しているか

## 7. 更新ルール
- UIの共通ルールを変更した場合は、本ファイルを先に更新する
- 変更理由は1〜2行で記録し、既存画面との互換性を確認する
