# 概要
`implementation` は設計に基づいて実装を進める Skill である。  
原則は「`docs/tasks.md` の未完了先頭タスクのみ実装する」。タスク粒度を超える実装は避ける。

# このSkillを使う場面
- `docs/tasks.md` にある未完了タスクを実装するとき
- 既存要件・設計が揃っており、実装に着手できるとき
- 小さく安全に変更して進捗を積み上げるとき

# このSkillを使わない場面
- 先に要件や設計の見直しが必要なとき
- 大規模な仕様変更の合意前で、前提が不安定なとき
- テスト追加のみが目的のとき（`test` を使う）

# 入力
- ユーザー依頼
- `AGENTS.md`
- `docs/requirements.md`
- `docs/design.md`
- `docs/tasks.md`（未完了先頭タスクを特定するため必須）
- 既存コードベース

# 出力
- 未完了先頭タスクに対応する最小限のコード変更
- 必要に応じた `docs/tasks.md` のステータス更新（`TODO/DOING/DONE/BLOCKED`）
- 実施した確認手順と結果、次に進むべきタスクの提示

# 作業手順
1. `AGENTS.md` と `docs/requirements.md` / `docs/design.md` を確認し、実装前提を揃える。
2. `docs/tasks.md` から未完了先頭タスクを1つ特定する（原則この1件のみ対応）。
3. 影響範囲が大きい場合は、変更内容・前提・影響を先に説明する。
4. タスク達成に必要な最小限のコード変更を行う。コードの意図が伝わりにくい箇所には、日本語コメントを適度に記述する。
5. 変更に対する最小限の確認（ビルド、実行、関連チェック）を行う。
6. `docs/tasks.md` のステータスを更新し、結果と次タスクを報告する。

# 禁止事項
- 未完了先頭以外のタスクへ無断で着手しない
- 要件や設計の未確定事項を実装で勝手に固定しない
- 一度に広範囲のリファクタや無関係変更を混ぜない
- 確認手順なしで完了扱いにしない

# 完了条件
- 未完了先頭タスク1件が実装され、目的が達成されている
- 実装内容が要件・設計と矛盾しない
- 確認手順と結果、次に進むべきタスクが明示されている
