# 概要
`test` は変更内容に対する検証を整える Skill である。  
原則は「変更に対する最小十分なテスト追加と確認手順の提示」。過剰な網羅より、リスクに見合う検証を優先する。

# このSkillを使う場面
- 実装変更に対して回帰防止テストを追加するとき
- 既存テストの不足を補い、確認可能性を高めるとき
- PR/レビュー前に実行手順と期待結果を明確化するとき

# このSkillを使わない場面
- 要件や設計の整理が未了で、テスト観点が定まらないとき
- 実装そのものが未着手で、検証対象が存在しないとき
- テストと無関係な文書変更だけを扱うとき

# 入力
- ユーザー依頼と変更内容
- `AGENTS.md`
- `docs/requirements.md`（受け入れ基準・業務ルール）
- `docs/design.md`（設計前提）
- `docs/tasks.md`（対象タスク）
- 変更済みコードと既存テスト

# 出力
- 変更に対する最小十分なテストコード追加/更新
- 実行した確認手順（コマンド、対象、期待結果）と実結果
- 未検証範囲や残リスクの簡潔な明示

# 作業手順
1. 変更対象と関連要件を確認し、守るべき振る舞いを特定する。
2. 既存テストを確認し、追加が必要な最小ケースを決める。
3. 変更点に直結するテストを優先して追加/更新する。
4. テスト実行コマンドと期待結果を明示し、実行結果を記録する。
5. 全面網羅が難しい場合は、未検証範囲と理由を明記する。
6. 必要に応じて `docs/tasks.md` の検証関連タスク状態を更新する。

# 禁止事項
- 変更と無関係な大量テスト追加で保守コストを増やさない
- 実行していない手順を実行済みとして報告しない
- 失敗結果や残リスクを隠さない
- 要件・設計と矛盾する期待値をテストに固定しない

# 完了条件
- 変更点を守るための最小十分なテストが追加または更新されている
- 確認手順と実結果が再現可能な形で提示されている
- 残リスクや未検証事項が必要に応じて明記されている
